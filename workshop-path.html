Kong AI Gateway workshop

Set up, govern, then extend

Stand up one model, my-model, and put governance on the traffic before an agent can spend it. Each stage adds one control in Konnect. The requests underneath prove that control, and the path ends when the MCP session shuts down.

Why each control exists

Stages 0 to 6

  • 0 The provider and my-model are in place. Hello Kong proves the proxy can reach the model with no key.
  • 1 Key auth comes before any other policy. Without the apikey header the call is rejected. With it, “Are you secure?” returns 200.
  • 2 The limit counts tokens, not HTTP calls. Two hundred tokens in sixty seconds. Requests 2.1 to 2.5 retell one long story until the gateway returns 429.
  • 3 The guard blocks meaning, not a keyword list. 3.1 asks what an API gateway is. 3.2 asks for investment advice and is denied.
  • 4 The cache serves a near-match. 4.1 misses. 4.2 asks the same thing in other words and hits.
  • 5 Routing picks the model for the prompt. 5.1 is a poem, 5.2 is strict JSON, 5.3 is ordinary chat.
  • 6 The caller does not own the system prompt. 6.1 decorates it. 6.2.1 sends a raw body and is blocked. 6.2.2 uses the support-query template.

Extend the gateway

7.0 through 7.7

  • A REST weather API becomes one MCP tool. The client never holds the upstream key.
  • 7.0 calls WeatherAPI directly, with gateway auth off.
  • 7.1 opens the session. 7.2 completes the handshake and expects 202.
  • 7.3 lists tools. The argument is query_q. 7.4 calls the tool for Bangkok.
  • 7.5 asks my-model for Tokyo weather and passes the tool list.
  • 7.6 sends that tool result back for the final answer.
  • 7.7 sends DELETE and shuts the session down.

Keep local

Private environment

  • Fill KONNECT_TOKEN, OPENAI_API_KEY, my-secret-key, and Mcp-Session-Id only in the private environment.
  • 7.6 stays empty until 7.5’s tool call is saved as final_messages_json.
  • local-env.template in git keeps those values blank.
